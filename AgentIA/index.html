🧠 Concepts essentiels

LLM (Grand modèle de langage)

Réseau de neurones entraîné sur du texte massif. Il prédit le « mot suivant » — et c'est tout ce qui fait sa force.

Token

Unité de texte (~4 caractères en anglais, moins en français). C'est la monnaie de la facturation et du contexte.

Contexte / Fenêtre

Tout ce que le modèle voit (instructions, historique, outils). Limité : il faut donner les infos utiles, rien de plus.

Agent

Un LLM « équipé » : il peut appeler des fonctions, lire une base, faire des requêtes HTTP — il raisonne, agit, observe, recommence.

💡 L'erreur n°1 : croire que le LLM « sait » les données de votre application. Il ne sait rien de privé : vous devez LUI fournir le contexte (RAG) ou lui laisser accéder à vos données (outils).

✍️ Prompt engineering

Les 5 règles d'or

1. Contexte → qui est l'utilisateur, pourquoi, à quoi sert la réponse 2. Rôle → « Tu es un correcteur de code senior » 3. Tâche → verbe d'action clair : explique, corrige, liste, génère 4. Format → sortie précise : JSON, liste, tableau, 5 points 5. Exemples → 1 à 2 exemples attendus (few-shot) --- Modèle de prompt structuré --- [SYSTÈME] Tu es un correcteur de code senior spécialisé en TypeScript. Tu réponds en français. Tu cites toujours le fichier et la ligne. [TÂCHE] Corrige les erreurs du code ci-dessous et explique chaque correction en 1 phrase. [SORTIE] - fichier: ligne — l'erreur - correction proposée en bloc de code - explication (1 phrase) [CODE] function add(a: string, b) { return a + b }

Techniques rapides

TechniqueExempleEffet
Zero-shot« Résume ce texte »Simple, général
Few-shot« Voici 2 exemples : … »Précision sur le format
Chain-of-thought« Raisonne pas à pas avant de répondre »Fiabilité sur le raisonnement
Réponse contrainte« Réponds uniquement par vrai ou faux »Déterministe, parseable
⚠️ Injection de prompt : si vous mettez le texte d'un utilisateur dans le prompt, il peut tenter « ignore les instructions précédentes ». Nettoyez / neutralisez les entrées utilisateur.

🦙 Ollama — exécuter un LLM SANS internet (en local)

# Installer et télécharger un modèle ollama run qwen2.5 # (open source, gratuit) ollama list # API HTTP locale compatible OpenAI curl http://localhost:11434/v1/chat/completions \ -H "Content-Type: application/json" \ -d '{"model":"qwen2.5","messages":[{"role":"user","content":"Résume en 1 phrase"}],"stream":false}'
💡 Pourquoi Ollama ? pas de clé API, pas de facturation, données qui ne quittent pas la machine. Idéal pour apprendre et prototyper (TP, projets scolaires). La carte graphique (GPU) accélère, mais même sans GPU on peut faire tourner un petit modèle.

🔌 Intégrer une API LLM dans votre code

Avec fetch (Node.js)

const OPENAI_URL = process.env.OPENAI_URL; // ex Ollama : http://localhost:11434/v1 const MODEL_PROMPT = process.env.MODEL_PROMPT || 'qwen2.5'; async function askModel(historique) { const r = await fetch(`${OPENAI_URL}/chat/completions`, { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ model: MODEL_PROMPT, messages: [ { role: 'system', content: 'Tu es un assistant technique maternelle (French).' }, ...historique ], 'temperature': 0.2, // 0 = le plus déterminé 'stream': false }) }); const data = await r.json(); return data.choices[0].message.content; }
👉 Où mettre la clé API ? jamais dans le front-end ni git — toujours un fichier .env (comme DATABASE_URL). Le front-end appelle VOTRE back-end qui, lui, appelle l'API du LLM.

🕵️ Agents & outils (function calling)

Un agent = LLM + boucle : le modèle décide d'appeler une fonction, on exécute, on lui rend le résultat, il recommence. Exemple : agent qui consulte vos produits puis répond.

// Les « outils » exposés à l'agent (structure minimale) const tools = [ { type: 'function', function: { name: 'recherche_bdd', description: 'Recherche des produits en base (PostgreSQL).', parameters: { type: 'object', properties: { mot: { type: 'string' } } } } } ]; // Le LLM peut répondre avec un appel d'outil... // {"name":"recherche_bdd","arguments":{"mot":"laptop"}} // → on exécute la requête SQL, on renvoie le résultat, on boucle.
ÉlémentRôle dans l'agent
BoucleRaisonner → choisir un outil → exécuter → observer
MémoireHistorique des messages / résumé pour suivre le fil
Outilsfonctions métier : SQL, HTTP, calculs, Redis, envoi d'email…
Garde-fousStop si boucle infinie, validation des sorties, budget tokens
⚠️ Un agent qui exécute du code = risque : il faut autoriser les outils (whitelist), limiter les actions et valider ce qui touche à l'argent / la suppression de données.

📚 RAG — donner vos documents au modèle

// 1. Découper les documents en morceaux // ex : chaque paragraphe = 1 « chunk » (+ résumé, tags) // 2. Calculer un vecteur (embedding) par chunk // → un tableau de nombres qui capture le SENS // 3. Stocker dans un store vectoriel (pgvector, Qdrant…) 👇 CREATE EXTENSION vector; -- table : (id, contenu, embedding vector(1024)) // 4. À la question : embedding de la question // + recherche des chunks les plus proches (proximité cosinus) // 5. Injecter ces chunks DANS le prompt `En te basant uniquement sur ces extraits : ----- ${chunks.join('\n')} ----- Réponds à : ${question}`
💡 Pourquoi RAG ? répondre sur SA documentation, SES produits, SON cours — sans réentraîner, avec les sources citées. C'est le pattern n°1 des applications IA en entreprise en 2026.

🤝 Éthique & limites

LimiteQue faire ?
HallucinationsVérifier les réponses, sources, température basse pour la fiabilité
Données personnellesNe jamais envoyer de PII dans le prompt sans consentement
Biais du modèleGarder un humain dans la boucle (review) pour les décisions
Coût / données quittent la machineUtiliser Ollama local quand c'est possible
FragilitéLe modèle peut casser : prévoir un fallback (message par défaut)
👉 L'agent IA dans TechTrends : un assistant qui « comprend » vos questions et applique des règles très précises (rôle de contrôleur qualité, prof, etc.) reste le meilleur cas d'usage pédagogique : pas d'abandon de contrôle, un outil augmenté.
