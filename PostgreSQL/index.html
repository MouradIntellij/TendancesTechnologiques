🚀 Démarrer PostgreSQL avec Docker

docker run -d \ --name db \ -e POSTGRES_DB=app \ -e POSTGRES_USER=app \ -e POSTGRES_PASSWORD=app \ -v pgdata:/var/lib/postgresql/data \ -p 5432:5432 \ postgres:16-alpine # Vérifier que le serveur répond docker exec db pg_isready -U app -d app

📝 Lire et écrire des données (DML)

INSERT

INSERT INTO produits (nom, prix, stock) VALUES ('Laptop XPS', 1499.99, 12); -- Plusieurs lignes d'un coup INSERT INTO produits (nom, prix, stock) VALUES ('Souris', 29.99, 100), ('Clavier', 79.99, 50); -- Récupérer l'id créé INSERT INTO produits (nom, prix) VALUES ('Écran', 399.00) RETURNING id, nom;

SELECT

SELECT id, nom, prix FROM produits; -- Filtrer, trier, limiter SELECT * FROM produits WHERE prix < 100 AND stock > 0 ORDER BY prix DESC LIMIT 10; -- Recherche partielle SELECT * FROM produits WHERE nom ILIKE '%laptop%'; -- ILIKE = insensible à la casse -- Compter et agréger SELECT COUNT(*), AVG(prix), MAX(prix), MIN(prix) FROM produits;

UPDATE / DELETE

UPDATE produits SET prix = prix * 1.1 WHERE id = 1; DELETE FROM produits WHERE id = 2; -- ⚠️ Toujours un WHERE pour UPDATE/DELETE ! UPDATE produits SET stock = 0; -- met TOUT à jour !
⚠️ Oublier le WHERE = désastre : DELETE FROM produits; sans condition vide la table. En production, on passe par des transactions (voir section dédiée).

🔗 Les jointures (JOIN)

INNER JOIN

Lignes présentes dans les DEUX tables.

LEFT JOIN

Toutes les lignes de gauche + les correspondances (« NULL » sinon).

RIGHT JOIN

Toutes les lignes de droite + les correspondances.

FULL OUTER JOIN

Tout, des deux côtés.

-- Chaque commande avec son client et ses produits SELECT c.nom AS client, co.date_commande, p.nom AS produit FROM commandes co JOIN clients c ON c.id = co.client_id JOIN details d ON d.commande_id = co.id JOIN produits p ON p.id = d.produit_id ORDER BY co.date_commande DESC; -- LEFT JOIN : les clients SANS commande (NULL) SELECT c.nom, co.id FROM clients c LEFT JOIN commandes co ON co.client_id = c.id WHERE co.id IS NULL;

GROUP BY & HAVING

-- Total des ventes par client SELECT c.nom, SUM(d.quantite * p.prix) AS total FROM details d JOIN produits p ON p.id = d.produit_id JOIN commandes co ON co.id = d.commande_id JOIN clients c ON c.id = co.client_id GROUP BY c.nom HAVING SUM(d.quantite * p.prix) > 100 ORDER BY total DESC; -- HAVING = filtre sur le GROUP BY ; WHERE = filtre avant regroupement
💡 Alias obligatoires pour l'agrégation : le alias AS total permet de trier sur le résultat agrégé. En Node/pg, c'est le nom de la colonne qu'on relit.

🏗️ Schéma & contraintes (DDL)

CREATE TABLE clients ( id SERIAL PRIMARY KEY, nom VARCHAR(100) NOT NULL, email VARCHAR(255) UNIQUE NOT NULL, cree_le TIMESTAMPTZ DEFAULT NOW() ); CREATE TABLE commandes ( id SERIAL PRIMARY KEY, client_id INTEGER NOT NULL REFERENCES clients(id), date_commande TIMESTAMPTZ DEFAULT NOW(), statut VARCHAR(20) DEFAULT 'en_attente' CHECK (statut IN ('en_attente', 'payee', 'annulee')) ); ALTER TABLE commandes ADD COLUMN total NUMERIC(10,2) DEFAULT 0; ALTER TABLE commandes DROP COLUMN total; DROP TABLE IF EXISTS commandes CASCADE;

⚡ Index & performance

CREATE INDEX idx_commandes_client ON commandes (client_id); CREATE UNIQUE INDEX idx_clients_email ON clients (email); -- Trouver les requêtes lentes EXPLAIN ANALYZE SELECT * FROM commandes WHERE client_id = 42; -- Voir l'index utilisé (Seq Scan vs Index Scan) DROP INDEX idx_commandes_client; -- supprimer si inutile
💡 Quand indexer ? Sur les colonnes utilisées dans WHERE, JOIN ON et ORDER BY fréquents. Ne pas tout indexer : chaque index ralentit les INSERT/UPDATE.

🔐 Transactions : tout ou rien

BEGIN; -- démarre la transaction UPDATE produits SET stock = stock - 1 WHERE id = 10; INSERT INTO commandes (client_id) VALUES (5); COMMIT; -- valide tout -- En cas d'erreur ou de doute : ROLLBACK; -- annule tout
CampSignification
COMMITValidation définitive
ROLLBACKAnnulation intégrale
👉 En Node/pg : on fait un BEGIN puis chaque requête. Si une promesse rejetée ⟶ ROLLBACK ; sinon COMMIT.

🧮 Fonctions & agrégats utiles

Fonctions de chaînes et de dates

SELECT CONCAT(nom, ' ', prenom) AS nom_complet; SELECT UPPER(email), LENGTH(nom); SELECT DATE_TRUNC('month', NOW()) AS debut_mois; SELECT EXTRACT(year FROM date_commande) AS annee; SELECT COALESCE(total, 0) AS total_sur; -- PLACE UNE 'INTERVAL' DANS UNE DATE SELECT date_commande + INTERVAL '7 days' AS echeance;
💡 COALESCE(x, valeur) remplace les NULL par une valeur de secours — très pratique pour éviter « null » dans vos réponses JSON d'API.

🔌 PostgreSQL + Node.js (avec le client pg)

npm install pg dotenv
import { Pool } from 'pg'; import dotenv from 'dotenv'; dotenv.config(); export const pool = new Pool({ connectionString: process.env.DATABASE_URL // postgres://app:app@db:5432/app }); // DELETE /api/produits/:id export async function supprimerProduit(id) { const result = await pool.query( 'DELETE FROM produits WHERE id = $1 RETURNING *', [id] ); return result.rows[0] ?? null; } // GET /api/produits/en-rupture export async function produitsEnRupture() { const result = await pool.query( `SELECT id, nom, prix, stock FROM produits WHERE stock = 0 ORDER BY nom` ); return result.rows; }
