⚙️ Démarrage & Configuration

TypeScript : c'est quoi ?

TypeScript = JavaScript + une couche de types (types statiques). Le compilateur tsc transforme le .ts en JavaScript pur, mais surtout il détecte les erreurs de type avant l'exécution. C'est du « JavaScript typé pour mieux coder ».

👉 Pourquoi utiliser TypeScript ?
  • Autocomplétion intelligente dans WebStorm / VS Code
  • Erreurs détectées à la compilation, pas en production
  • Refactoring sans crainte (le compilateur guide)
  • Documentation vivante grâce aux types

Installation (npm)

// Installation locale (recommandé dans un projet) npm install -D typescript # TypeScript 7.x (compilateur natif Go) // Installation globale npm install -g typescript // Vérifier la version tsc --version // 7.0.x — environ 10× plus rapide que 5.x npx tsc --version // version locale du projet
💡 Depuis TS 6.0 : le mode strict est activé par défaut (avant il fallait l'activer). Depuis TS 7.0, le compilateur est écrit en Go : builds beaucoup plus rapides.

tsconfig.json — la configuration (WebStorm génère ce fichier)

{ "compilerOptions": { "target": "ES2024", // Version JS générée "module": "NodeNext", // Système de modules (ESM moderne) "moduleResolution": "NodeNext", "rootDir": "./src", // Dossier source "outDir": "./dist", // Dossier généré "strict": true, // ✅ Activé par défaut en TS 6+ "noEmitOnError": true, "skipLibCheck": true, "verbatimModuleSyntax": true, // Import de types explicites "erasableSyntaxOnly": true // TS 5.8+ : syntaxe compatible Node }, "include": ["src"] }
⚠️ Strict mode : strict: true active : noImplicitAny (interdit les types implicites any), strictNullChecks (force la gestion de null/undefined), noUnusedLocals, etc. C'est LA bonne pratique enseignée aujourd'hui.

Compilation

npx tsc // Compile selon tsconfig.json npx tsc --watch // Recompile à chaque sauvegarde npx tsc --noEmit // Vérifie les types SANS générer de JS npx tsc src/app.ts // Compile un fichier précis // Avec Node.js 24+ : exécution directe de .ts natif (type stripping) node src/app.ts // ✅ Node exécute du TypeScript directement
💡 WebStorm : WebStorm utilise le language server de TypeScript. Créez un projet vide, activez « Built-in TypeScript » (Settings → Languages & Frameworks → TypeScript) et sélectionnez la version du projet (node_modules/typescript). Ajoutez un Run Configuration pour exécuter node --watch ou un script npm.

⚠️ any vs unknown :
  • any désactive TOUTE vérification — équivalent JavaScript pur.
  • unknown force une vérification avant utilisation — plus sûr.
unknown est la bonne réponse aux données externes (API, JSON parses).

🧩 Types Avancés

Union types (|)

// Une valeur qui peut être de plusieurs types let id: string | number = 'abc123'; id = 456; // ✅ OK, number est dans l'union type Statut = 'actif' | 'inactif' | 'suspendu'; const etat: Statut = 'actif'; // Narrowing : TS réduit le type automatiquement dans un if function doubler(valeur: string | number): number { if (typeof valeur === 'string') { return valeur.length * 2; // TS sait que 'valeur' est string ici } return valeur * 2; // et number ici }

Literal types

// Type littéral : une valeur exacte let direction: 'gauche' | 'droite' = 'gauche'; // direction = 'haut'; // ❌ Erreur : 'haut' n'est pas autorisé const PI = 3.14; // type : 3.14 (literal) type Direction = 'haut' | 'bas' | 'gauche' | 'droite'; type CodeHttp = 200 | 400 | 404 | 500;

Intersection types (&)

type DateDisponible = { debut: string }; type Lieu = { salle: string, batiment: string }; // Intersection : combine les deux structures type Cours = DateDisponible & Lieu; // Cours = { debut: string, salle: string, batiment: string } const cours: Cours = { debut: '2026-01-12', salle: 'A-200', batiment: 'S4' };

Enums — ⚠️ usage recommandé

// ❌ enum classique : code généré, incompatible erasableSyntaxOnly enum Couleur { Rouge = 'rouge', Vert = 'vert' } // ✅ Recommandé moderne : union de literals (erasable, TS 5.8+/node) type Couleur = 'rouge' | 'vert' | 'bleu'; const couleurs = { Rouge: 'rouge', Vert: 'vert', Bleu: 'bleu', } as const; // objet readonly type-safe // const enum : compilé à la volée mais interdit sous eraSyntaxOnly
💡 Pourquoi éviter enum ? Depuis TS 5.8, le mode erasableSyntaxOnly (recommandé pour Node.js 24+ qui exécute nativement le TypeScript) interdit les enums, namespaces et paramètres de constructeurs dits « non-erasables » : le code doit pouvoir être effacé de ses types sans transformation. Préférez union types + objets as const.

sinon : Record, Index Signature et Tableaux tuples lus

// Index signature : objet à clés dynamiques interface Traductions { [langue: string]: string; } const t: Traductions = { fr: 'Bonjour', en: 'Hello' }; // Tuple readonly (immutable) const point: readonly [number, number] = [3, 5]; // point[0] = 9; // ❌ readonly // Optional property (?) interface Config { url: string; porto?: number; // optionnel : number | undefined }

satisfies — vérifie le type sans perdre la précision

type Routes = Record<string, string[]>; // satisfies : TS vérifie que l'objet respecte Routes… const routes = { '/': ['home'], '/api': ['GET', 'POST'], } satisfies Routes; routes['/'].push('about'); // ✅ OK, TS garde le type précis

📐 Interfaces & Type Aliases

Interface vs Type

// Interface : décrit la STRUCTURE d'un objet interface Utilisateur { id: number; nom: string; email: string; age?: number; // optionnel } // Type alias : idem, mais plus flexible type Utilisateur2 = { id: number; nom: string; email: string; }; // ⚡ Même démarche moderne : prefer interface pour objets, type pour le reste
💡 Règle générale : une interface peut être étendue (declaration merging) et extends ; un type peut faire des unions/intersections/mapped types. Pour un objet simple, les deux conviennent — la communauté moderne utilise surtout type et interface selon le style du projet.

Extends (héritage d'interfaces)

interface Animal { nom: string; age: number; } interface Chien extends Animal { race: string; aboyer(): string; } const rex: Chien = { nom: 'Rex', age: 3, race: 'Labrador', aboyer: () => 'Wouf!' }; // Interface avec méthodes (callbacks, fonctions) interface HttpClient { get(url: string): Promise<unknown>; post(url: string, body: unknown): Promise<unknown>; }

optional & readonly

interface Produit { readonly id: number; // non modifiable après création nom: string; prix: number; description?: string; // optionnel } const p: Produit = { id: 1, nom: 'Laptop', prix: 1200 }; // p.id = 5; // ❌ readonly p.nom = 'Ultrabook'; // ✅ OK

Header de fonction avec interface

// Signature de fonction typée interface Formatter { (valeur: number, devises: string): string; } const formatterEuro: Formatter = (montant, devise) => montant.toLocaleString('fr-FR', { style: 'currency', currency: devise }); // index signature + propriétés mixtes interface Cache { [cle: string]: string | number; } const cache: Cache = { utilisateur: 123, session: 'abc' };

Classe de base

class CompteBancaire { private solde: number; // inaccessible à l'extérieur readonly numero: string; // constante après init constructor(numero: string, soldeInitial = 0) { this.numero = numero; this.solde = soldeInitial; } deposer(montant: number): void { if (montant <= 0) throw new Error('Montant invalide'); this.solde += montant; } consulterSolde(): number { return this.solde; } } const compte = new CompteBancaire('A-100', 500); compte.deposer(200); // console.log(compte.solde); // ❌ private console.log(compte.consulterSolde()); // 700

Héritage, override et abstract

💡 implements : une classe peut implémenter une interface (contrat) sans hériter de code : class Developpeur implements Personne { ... }. 💡 Parameter properties : constructor(private solde: number) déclare + initialise en une ligne.

Getters et Setters

class Temperature { constructor(private celsius: number) {} get fahrenheit(): number { return (this.celsius * 9) / 5 + 32; } set fahrenheit(valeur: number) { this.celsius = ((valeur - 32) * 5) / 9; } } const t = new Temperature(25); console.log(t.fahrenheit); // 77 t.fahrenheit = 104; // setter

🎯 Fonctions Typées

Annotations de paramètres et de retour

function additionner(a: number, b: number): number { return a + b; } // Fonction fléchée const multiplier = (a: number, b: number): number => a * b; // Paramètre optionnel (?) function saluer(nom: string, titre?: string): string { return titre ? `${titre} ${nom}` : nom; } // Paramètre par défaut function configurer(porto: number = 3000, hote = 'localhost'): string { return `${hote}:${porto}`; } // Rest parameters function somme(...nombres: number[]): number { return nombres.reduce((acc, n) => acc + n, 0); }

Type de retour void et never

// void : rien à retourner function afficherErreur(message: string): void { console.error(message); } // never : ne retourne JAMAIS (throw ou boucle infinie) function erreurFatal(): never { throw new Error('Erreur irrécupérable'); } // never utile pour l'exhaustivité d'un switch function verifierStatut(statut: Statut): string { switch (statut) { case 'actif': return 'OK'; case 'inactif': return 'KO'; default: const jamais: never = statut; // erreur si un cas est oublié return jamais; } }

Callbacks et fonctions comme valeurs

type Operation = (a: number, b: number) => number; function executer(a: number, b: number, operation: Operation): number { return operation(a, b); } const addition: Operation = (x, y) => x + y; executer(5, 3, addition); // 8 executer(5, 3, (x, y) => x * y); // 15 // map / filter typés const nombres: number[] = [1, 2, 3, 4]; const doublés: number[] = nombres.map(n => n * 2); const pairs: number[] = nombres.filter(n => n % 2 === 0); const total: number = nombres.reduce((acc, n) => acc + n, 0);

// Signatures multiples pour meilleure précision function convertir(valeur: number): string; function convertir(valeur: string): number; function convertir(valeur: number | string): number | string { if (typeof valeur === 'number') { return valeur.toString(); } return Number(valeur); } const s: string = convertir(123); // TS sait que c'est string const n: number = convertir('123'); // TS sait que c'est number

🔄 Génériques

Les génériques permettent de créer du code réutilisable tout en gardant les types précis, au lieu de retomber dans any.

Fonction générique

// T = paramètre de type générique function <T>identite(valeur: T): T { return valeur; } const chaine = identite('abc'); // TS infère : identite const num = identite(42); // TS infère : identite // Fonction générique fléchée (syntaxe TSX séparée) const premier = <T, TListe extends T[]>(tableau: TListe): T => tableau[0];

Types génériques

// Type générique pour une réponse API interface ApiResponse<T> { succes: boolean; donnees: T | null; message?: string; } interface Utilisateur { id: number; nom: string; } const reponse: ApiResponse<Utilisateur> = { succes: true, donnees: { id: 1, nom: 'Alice' } }; // Type générique pour une boîte/collection type Resultat<Reussite, Echec> = | { ok: true; valeur: Reussite } | { ok: false; erreur: Echec };

Contraintes (extends)

// T doit avoir un propriété 'length' function <T extends { length: number }>longueur(valeur: T): number { return valeur.length; } longueur('abc'); // 3 (string) longueur([1, 2, 3]); // 3 (array) // longueur(42); // ❌ number n'a pas de .length // Contrainte sur une propriété clé function <T, K extends keyof T>obtenirValeur(obj: T, cle: K): T[K] { return obj[cle]; } obtenirValeur({ nom: 'Alice', age: 30 }, 'nom'); // string obtenirValeur({ nom: 'Alice', age: 30 }, 'age'); // number // obtenirValeur({nom:'Alice'}, 'adresse'); // ❌ n'existe pas

Classe générique

class Pile<T> { private elements: T[] = []; empiler(element: T): void { this.elements.push(element); } depiler(): T | undefined { return this.elements.pop(); } taille(): number { return this.elements.length; } } const pileChaines = new Pile<string>(); pileChaines.empiler('A'); // pileChaines.empiler(42); // ❌ number non accepté const pileNombres = new Pile<number>(); pileNombres.empiler(10);

Type Parameters & inference avancée

// Le premier argument contrôle les types suivants function <C extends string>creerObjet(cle: C, valeur: number): Record<C, number> { return { [cle]: valeur } as Record<C, number>; } // const type parameters (TS 5.0+): préserve la précision des literals function <const T extends string[]>valeurs(arr: T): T { return arr; } const v = valeurs(['a', 'b']); // type : readonly ["a", "b"]

Mapped Types (transformation de types)

// Créer un type à partir des clés d'un autre type Drapeaux = { [K in keyof Utilisateur]: boolean }; // { id: boolean; nom: boolean; email: boolean; motDePasse: boolean; } // Rendre optionnel manuellement (= Partial) type Optionnel<T> = { [K in keyof T]?: T[K] }; // Modifier l'accès (readonly / -readonly) type Mutable<T> = { -readonly [K in keyof T]: T[K] };

import express, { Request, Response } from 'express'; interface Technologie { id: number; nom: string; categorie: string; } const technos: Technologie[] = []; const app = express(); app.use(express.json()); // Appel API tape JSON typéral app.get('/api/technos', (_req: Request, res: Response) => { res.json(technos); }); app.post('/api/technos', (req: Request, res: Response) => { // null body guard + typer le corps attendu const corps = req.body as Omit<Technologie, 'id'>; if (!corps?.nom || !corps?.categorie) { res.status(400).json({ erreur: 'nom et categorie requis' }); return; } const nouvelle: Technologie = { id: technos.length + 1, ...corps }; technos.push(nouvelle); res.status(201).json(nouvelle); }); app.listen(3000, () => console.log('Serveur démarré sur :3000'));

PostgreSQL avec node-postgres (pg)

import { Pool } from 'pg'; interface LigneProduit { id: number; nom: string; prix: number; } const pool = new Pool({ connectionString: process.env.DATABASE_URL, }); async function getProduits(): Promise<LigneProduit[]> { const { rows } = await pool.query<LigneProduit>( 'SELECT id, nom, prix FROM produits ORDER BY id' ); return rows; } // Paramètres typés (évite l'injection SQL) async function trouverProduit(id: number): Promise<LigneProduit | undefined> { const { rows } = await pool.query<LigneProduit>( 'SELECT id, nom, prix FROM produits WHERE id = $1', [id] ); return rows[0]; }

import { createClient } from 'redis'; const client = createClient({ url: process.env.REDIS_URL }); await client.connect(); async function mettreEnCache<T>(cle: string, valeur: T, ttlSec: number = 60) { await client.setEx(cle, ttlSec, JSON.stringify(valeur)); } async function lireCache<T>(cle: string): Promise<T | null> { const brut = await client.get(cle); return brut ? (JSON.parse(brut) as T) : null; } // Utilisation : cache-first const cache = await lireCache<LigneProduit[]>('produits'); if (cache) { return cache; } const produits = await getProduits(); await mettreEnCache('produits', produits, 120);

Docker + TypeScript (multi-stage build)

# Dockerfile (2 étapes : build TS → image d'exécution minimale) FROM node:22-alpine AS build WORKDIR /app COPY package.json package-lock.json ./ RUN npm ci COPY src ./src COPY tsconfig.json ./ RUN npx tsc # compile .ts → dist/ FROM node:22-alpine WORKDIR /app COPY --from=build /app/dist ./dist COPY package.json ./ RUN npm ci --omit=dev ENV NODE_ENV=production EXPOSE 3000 CMD ["node", "dist/server.js"]
